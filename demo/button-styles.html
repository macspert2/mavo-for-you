Styles de boutons — dix idées et un jeu complet

Each card shows a live button and, beneath it, the five states frozen side by side — rest, hover, active, focus, disabled — because you cannot fake :hover in CSS and hunting for each state one at a time is no way to judge a set.

The constraint that rules out half the internet's button styles: input[type="submit"] cannot have ::before or ::after. Several of this site's buttons are inputs — the comment submit, the search submits — so anything built on a pseudo-element is unusable there, however nice it looks. Every card says which markup it needs. Eight of the ten work anywhere.

La galerie

Nothing here reflows on interaction: movement comes from transform, depth from box-shadow, and borders are declared at rest even when transparent, so a button that gains one on hover does not shove its neighbours sideways.

Un jeu pour Maman Voyage

Three tiers, one motion language. The primary is what is already live; the other two are built from the same palette and the same stamp, so a row containing all three reads as one family rather than three decisions.

Primaire · Secondaire · Tertiaire

Blue fill for the one action that matters, a warm outline for the alternative, and a text button for everything that should not compete. Only the first two rotate.

Full width, and therefore no rotation: at 1.2° the corners of a 600px button travel about six pixels and it reads as broken rather than stamped. It lifts instead.

Disabled is one treatment for the whole set — greyed, desaturated, and with movement switched off entirely, so a dead button cannot pretend to respond. 

/* Tier 1 — the one already live */
.mv-btn-1 { background-color: #4e74a5; color: #fff; }
.mv-btn-1:hover  { transform: rotate(-1.2deg); filter: brightness(.96); }
.mv-btn-1:active { transform: rotate(.4deg) scale(.98);
                   outline: 5px dashed color-mix(in srgb, currentColor 60%, transparent);
                   outline-offset: -5px; }

/* Tier 2 — the alternative, never the same weight as tier 1 */
.mv-btn-2 { border: 2px solid #886353; color: #5c3d2e; }
.mv-btn-2:hover  { background-color: #886353; color: #fff; transform: rotate(-1deg); }

/* Tier 3 — a link that happens to be a button */
.mv-btn-3 { color: #4e74a5; background: linear-gradient(#886353,#886353) 0 100% / 0% 2px no-repeat; }
.mv-btn-3:hover  { color: #5c3d2e; background-size: 100% 2px; }

Trois choses à savoir

Deux pseudo-éléments, trois idées

Cards 11 and 12 exist because the obvious way to build them does not work. Billet used ::before and ::after for its two notches, and Flèche needs ::after for its arrow — and an element has only two pseudo-elements. So the notches are painted as radial-gradient backgrounds instead, which frees both.

Card 11 is still <button>-only, because the arrow itself needs ::after. Card 12 drops the arrow and is therefore the one that can go on an input[type="submit"] — the comment submit, the search submits — notches, tilt, perforation and all.

The cost is that a painted notch is opaque: it has to be the colour of whatever sits behind the button, set through --billet-bg. Get it wrong and the notches read as two pale blobs rather than holes. That is also why this variant darkens with background-color and not filter: brightness() — a filter would darken the notches too, and they would stop matching the page on hover.

Pourquoi la rotation dépend de la largeur

A rotation pivots about the centre, so each edge moves by half the width times the sine of the angle. At 1.2° that is about 1.6px on a 150px button — a tilt — and about 6px on a 600px one, which reads as a mistake. Rotate small buttons; lift wide ones. That is the whole reason .mv-stamp--press exists.

Pourquoi filter plutôt qu'une couleur

filter: brightness(.96) darkens whatever background it finds, so one rule works on a blue button, a white one and a warm outline alike. Naming a hover colour instead would mean naming one per variant, and every new variant would need another. The cost is that it darkens the label too, which at these values is imperceptible and arguably right — ink presses harder.

L'état désactivé n'est pas optionnel

A disabled button that still lifts, tilts and brightens on hover is lying about being clickable. The base here switches movement off with transform: none !important — one of the few places that keyword earns its place, since it has to beat every variant's own hover rule at once.
